## Why this vault exists

Useful AI instructions often end up scattered across plugin folders, downloaded archives, project notes, and different tools. Finding the right version becomes its own task.

This vault brings those materials into a consistent browsing and download structure:

- **Start with your task.** Topic folders help you narrow the collection without learning its technical structure.
- **Skip the packaging chores.** Available skill downloads are already zipped individually.
- **Read before you install.** Plain-text references let you inspect a skill's instructions before deciding to use it.
- **See the requirements.** Tool-dependent packages and incomplete packages are distinguished from packaging-checked downloads.
- **Keep the source.** Original copies, meaningful variants, attribution, and technical reports remain available under Advanced.
- **Choose your preferred interface.** Use Finder, GitHub's Markdown catalog, or the optional local HTML browser.

The goal is simple: spend less time locating and preparing instructions, and more time applying the right ones to your work.

## Understand the readiness labels

**Packaging checked** means the export passed the library's packaging checks and no special setup signals were detected. It does **not** mean the skill has been imported into Claude, independently security-audited, or proven to work with your account.

**Needs tool/setup review** means a ZIP exists, but the material mentions requirements such as connected services, scripts, credentials, plugins, host-specific features, or developer tools. Read the linked reference before uploading. Automated flags can over-detect or miss requirements.

**Needs repair** means required resources were missing or could not be safely included. These entries are listed rather than shipped as misleadingly complete downloads.

**Command—not a skill ZIP** means the entry is a command-oriented artifact. Claude Code commands and Claude-app skills are not interchangeable installation formats.

## Upload to Claude

1. **Choose one relevant skill.** Start with a small task rather than installing the whole collection.
2. **Read its guidance and reference.** Check which tools, permissions, and inputs it expects.
3. **Upload the individual ZIP** using Claude's skill-upload control.
4. **Test with harmless sample data.** Confirm that the skill loads and behaves as expected before using sensitive or production material.

Use Claude's **Skills** settings, not a normal chat attachment, to install a
native skill. Interface labels and account permissions may vary.
[Official upload instructions](https://support.claude.com/en/articles/12512198-how-to-create-custom-skills).

You do not need to create ZIPs yourself. Do not upload the entire vault as one
skill. Pick the skills you need and avoid installing different versions with
the same skill name together.

**No live Claude imports are verified by this library.** If a skill fails to import or asks for unavailable tools, keep the original ZIP, note the exact error, and review its requirements. Do not assume that renaming the ZIP will fix a compatibility issue.

## A sensible first session

1. Pick a small, concrete task—for example, reviewing a draft or planning a feature.
2. Browse the relevant topic and read one candidate's reference.
3. Choose either the skill package or the readable guidance appropriate to your environment.
4. Supply a clear objective, relevant context, and the output format you want.
5. Review the result yourself, then keep a note of what worked and what required adjustment.

Example task brief:

> Help me review this draft for clarity. Use the relevant guidance I supplied, identify the three most important improvements, and explain each suggestion. Do not invent facts or change the original file without my approval.

This is a starting prompt, not a special activation command. The useful part is making the task, boundaries, and expected result explicit.

## Frequently asked questions

### Do I need the website or Terminal?

Not to download and browse the library or select prepared ZIPs. The HTML page is optional. Individual skills may require additional software or technical setup; check their status and reference.

### Can I upload the whole vault as one skill?

No. The complete download contains many independent packages, references, commands, and maintenance files. Pick an individual skill ZIP instead.

### Can I use the readable material with another AI assistant?

You can evaluate the plain-text guidance for use in another environment, subject to its license and that product's capabilities. This repository does not certify cross-platform compatibility. A Claude-format ZIP is not a universal installer, and provider-specific tool instructions may need adaptation.

### Does downloading a skill connect its services automatically?

No. A file cannot grant access to your accounts. Review any required integrations separately and provide only the permissions genuinely needed for your task.

### Why are so many packages in NEEDS SETUP?

The library uses conservative requirement flags. A package mentioning an external tool or host feature is separated for review rather than presented as a guaranteed plug-and-play download. A flag is a reason to inspect, not proof that the skill is broken.

### Can I share or sell the collection?

Do not assume so. Materials come from multiple authors and ecosystems. Each item's permissions must be reviewed independently, and there is no repository-wide license overriding third-party rights. Private access does not itself grant resale or redistribution permission.

### Where should I report a problem?

With repository access, [open an issue](https://github.com/QuntmTech/ai-skills-vault-unlocked/issues) containing the skill name or catalog ID, package filename, target application, and exact error. Remove credentials, personal information, and private project content before sharing screenshots or logs.

## Safety, provenance, and maintenance

Treat downloaded instructions and scripts as material to inspect—not automatic authority to run commands, access accounts, or change files. Test new workflows with non-sensitive data, review permissions, and keep credentials out of prompts and shared templates.

The library includes automated catalog checks, package validation, ZIP integrity checks, and tests for its maintenance tooling. Those checks help detect packaging and consistency problems; they do not establish that every included instruction is safe or effective.
